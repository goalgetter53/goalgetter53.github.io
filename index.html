01

Signal-based outbound engine

Outbound · Enrichment · ICP scoring

Problem
Static lead lists burn domains and get under 1% replies. Teams need to reach accounts when they're actually buying.
Built
A pipeline that detects hiring, funding and tech-stack signals, then enriches contacts through a provider waterfall that stops at the first verified hit. It scores each account against a weighted ICP, has Claude write a first line per contact, and exports a ready-to-send Instantly CSV with a cost and coverage report. A matching Clay table spec is included.

03

Clay → HubSpot sync in n8n

CRM integration · Data hygiene

Problem
Enriched data dies in spreadsheets, and manual imports create duplicate CRM records.
Built
An importable n8n workflow. A Clay webhook feeds validation and normalization, then dedupe by email and then by domain, then upserts Company and Contact records and associates them. It retries with backoff on 429/5xx and sends failures to a dead-letter branch. A YAML field map and a test harness replay bad payloads. It mirrors my own Clay → CRM pipeline.

04

Cold email deliverability kit

Infrastructure · DNS · Warmup

Problem
Great copy is worthless if it lands in spam. Most outbound programs fail at the infrastructure layer.
Built
A CLI that audits SPF (including the 10-lookup limit), DKIM, DMARC and MX. It prints the exact DNS records to add, suggests secondary outreach domains, and generates a warmup and ramp schedule with inbox rotation. It ships with a full deliverability SOP that follows Gmail, Yahoo and Outlook bulk-sender rules.

05

Claude inbound lead agent

AI agent · Speed-to-lead · Routing

Problem
Inbound leads wait hours for a reply while reps spend time on poor fits.
Built
A FastAPI service with a Claude tool-use agent. It researches the lead's company site, checks the CRM, and returns validated JSON with ICP score, intent, route (AE, nurture, self-serve or disqualify) and a draft reply. Fetched web text gets prompt-injection guardrails. It includes an eval harness and an MCP server so Claude Code can qualify leads directly.

How I work

GTM engineering is revenue problems first and tools second.

1 · Diagnose

Start from the funnel. Where is pipeline leaking: targeting, data, copy, deliverability or speed-to-lead? Define the ICP before building anything.

2 · Build

Use Clay and n8n where they're fastest, and Python, APIs and Claude agents where they hit limits. Version-control everything and document it for handover.

3 · Measure

Track coverage, cost per enriched contact, reply and meeting rates. Run weekly experiments and cut what doesn't move pipeline.
